# Auth Service

Handles user registration, authentication, and token lifecycle management. It is the only service that issues JWTs and the only service that interacts with credential storage (passwords).

---

## Overview

| | |
|---|---|
| **Port** | `8081` |
| **Context path** | `/auth` |
| **Framework** | Spring Boot 4.x + Spring Security |
| **Java** | 25 |
| **Database** | PostgreSQL — `users` table |
| **Cache** | Redis — refresh token storage and invalidation |

---

## Responsibilities

- Register new users and create their credential record
- Authenticate users and issue JWT access + refresh token pairs
- Refresh access tokens using a valid refresh token
- Invalidate refresh tokens on logout
- Notify the **User Service** to create a profile after successful registration
- Provide an internal endpoint for other services to verify user credentials

---

## API Endpoints

### Public (no JWT required)

| Method | Path | Description |
|---|---|---|
| `POST` | `/auth/register` | Register a new user |
| `POST` | `/auth/login` | Authenticate and receive tokens |
| `POST` | `/auth/refresh` | Exchange refresh token for new token pair |
| `POST` | `/auth/logout` | Invalidate the refresh token |

### Internal (service-to-service only, blocked at gateway)

| Method | Path | Description |
|---|---|---|
| `GET` | `/auth/internal/{id}/exists` | Check if a user ID exists |
| `POST` | `/auth/internal/{id}/deactivate` | Deactivate user credentials (called by User Service on delete) |

## JWT Design

### Token Types

| Token | TTL | Purpose |
|---|---|---|
| Access Token | 15 minutes | Authenticate API requests (sent in `Authorization` header) |
| Refresh Token | 7 days | Obtain a new access token when the current one expires |

### Claims (Access Token)

```json
{
  "sub": "44d609a0-2fb5-4c15-8edd-cb04c76f6150",   // user UUID — used as userId across all services
  "username": "asadshaikh",
  "role": "USER",
  "type": "access",
  "iat": 1748000000,
  "exp": 1748000900
}
```

### Algorithm

`HMAC-SHA256` (HS256) with a 256-bit Base64-encoded shared secret.

> The same secret must be configured in every service that validates JWTs (gateway, user, chat, message, notification).

### Refresh Token Storage

Refresh tokens are stored in **Redis** with a TTL matching the token expiration (7 days). On logout, the token is deleted from Redis, making it immediately invalid even before it naturally expires.

---

## Rate Limiting

Authentication endpoints are protected against brute-force attacks:

- **10 requests per minute** per IP address using [Bucket4j](https://github.com/bucket4j/bucket4j)
- Exceeding the limit returns `429 Too Many Requests`
- Buckets are stored in-memory per service instance

## Registration Flow

```
POST /auth/register
    1. Validate input (unique email, unique username, password length)
    2. Hash password with BCrypt
    3. Save credentials to PostgreSQL (users table)
    4. Generate access + refresh token pair
    5. Call User Service → POST /users/ to create public profile
    6. Return tokens to client
```

Step 5 uses a Feign client. If the User Service is unavailable, registration fails and is rolled back.

## Database Schema

```sql
CREATE TABLE users (
    id           VARCHAR PRIMARY KEY,          -- UUID generated by auth service
    username     VARCHAR UNIQUE NOT NULL,
    email        VARCHAR UNIQUE NOT NULL,
    password     VARCHAR NOT NULL,             -- BCrypt hashed
    role         VARCHAR NOT NULL DEFAULT 'USER',
    is_active    BOOLEAN NOT NULL DEFAULT true,
    is_deleted   BOOLEAN NOT NULL DEFAULT false,
    created_at   TIMESTAMP NOT NULL,
    updated_at   TIMESTAMP
);
```

> **Note:** This table stores **credentials only**. Display names, bios, avatars, and status are managed by the User Service in a separate `user_profiles` table.

## Configuration

```properties
# application-dev.properties
server.port=8081

spring.datasource.url=jdbc:postgresql://localhost:5432/chatapp
spring.datasource.username=postgres
spring.datasource.password=postgres

spring.data.redis.host=localhost
spring.data.redis.port=6379

jwt.secret=<base64-encoded-256-bit-key>
jwt.access-token.expiration=900000      # 15 minutes in milliseconds
jwt.refresh-token.expiration=604800000  # 7 days in milliseconds

eureka.client.service-url.defaultZone=http://localhost:8761/eureka/
```

```bash
openssl rand -base64 32
```

## Security Notes

- Passwords are hashed with **BCrypt** (cost factor 10) — never stored in plaintext
- The `users` table uses **soft delete** (`is_deleted = false` filter via `@SQLRestriction`) — records are never physically removed
- All sensitive fields (password, tokens) are masked in logs via `MaskingConverter` in Logback configuration
